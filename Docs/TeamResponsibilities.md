# Proposed four-person modules

| Member slot | Main files | What to explain and review |
|---|---|---|
| 1 — Student | `Student/StudentDashboard.html`, `Student/JS/StudentDashboard.js` | Weighted GPA, dynamic rows, checkbox totals, prerequisite explanations, and resets. |
| 2 — Administrator | `Admin/AdminDashboard.html`, `Admin/JS/AdminDashboard.js` | Code/credit validation, duplicate checking, array additions, and case-insensitive search. |
| 3 — Faculty Advisor | `Advisor/AdvisorDashboard.html`, `Advisor/JS/AdvisorDashboard.js` | Student/course selection, conditional comment length, note rendering, and plan status updates. |
| 4 — Academic Coordinator | `Coordinator/CoordinatorDashboard.html`, `Coordinator/JS/CoordinatorDashboard.js` | Offering fields, duplicate/faculty-time checks, filters, and schedule rows. |

These are proposed assignments, not authorship claims. The initial implementation was prepared with a coding assistant under the coordinator's direction. Record each teammate's actual edits, tests, and reviews when they happen; do not fabricate contributions or commits.

Shared changes to `JS/Common.js`, `JS/AcademicData.js`, or `Design/Style.css` should be reviewed together because all modules use them. Existing login and role-registration files remain a shared foundation.

Each member should demonstrate one valid submission, one invalid submission, a reset, and the resulting DOM update. They should also explain why data changes disappear after navigation or refresh.
